## How the pipeline works

**Body.** `make_human()` builds the MPFB body + "default" rig at the world origin, facing −Y,
feet on z=0. Rig object at identity, so armature space = world space. Bone names:
`root`, `spine05..01`, `neck01..03`, `head`, `pelvis.L`, `upperleg01/02.L`,
`lowerleg01/02.L`, `foot.L`, `clavicle.L`, `shoulder01.L`, `upperarm01/02.L`,
`lowerarm01/02.L`, `wrist.L`, `metacarpal1-4.L`, `finger1-1..5-3.L` (+ `.R`).
Limbs are split in two bones (01/02); the solver rotates 01 and leaves 02 at rest
relative to it.

**Pose solver (`Poser`).** Per frame: `reset()` → place `root` (rotation = pelvis hinge,
translation chosen so the hip-joint midpoint lands on a planned path) → spine/neck/head
small local rotations → `limb()` for each leg/arm.
- `limb(upper, lower, end, target, pole, palm=None, side=None)`: analytic two-bone IK.
  The middle joint (knee/elbow) is placed toward `pole`; the upper segment's twist comes
  from the rest bend direction → current bend direction. If `palm` is given (a world
  vector), the forearm's twist is set so the palm faces that way (pronation/supination).
- Legs: pole = the toe direction → knees always track the toes (this fixed the crossing).
- Arms: **pass the planned elbow as the pole**
  (`(elbow - sh) - (elbow - sh).project(wrist - sh)`), otherwise the elbow drifts at deep
  flexion (it flared 20 cm on the curl).
- `curl_fingers(side)`: positive angles about local X = fist (verified on the left hand).
- Every frame is keyframed (`rotation_quaternion` + `location` on all pose bones), so
  the .blend files in `review/` replay the animation and can later export to GLB.

**Tempo.** 72 frames at 30 fps per loop: hold, concentric/eccentric with smoothstep,
pause, hold. Frame 1 == frame 72 so it loops.

**Muscles.** `muscle_material(primary, secondary)` mixes the grey base with red/orange
using the mask channels (`mask_slot(group)` → image index, channel). Masks come from
`build_muscle_maps.py`:
1. Append Z-Anatomy's `4: Muscular system` + `1: Skeletal system` collections; drop
   fascia/bursa/sheath/septum/retinaculum/tract meshes (but keep tensor fasciae latae).
2. Joint landmarks from the bone meshes (femoral head, condyles, talus, humeral head,
   elbow, lunate) ↔ MPFB rest joints. Each muscle moves with one segment
   (rotate + stretch along the segment axis); trunk muscles are forced to the torso.
3. Torso depth refit: Z-Anatomy's torso is ~27% deeper front-to-back than MPFB's.
4. Join meshes per group (17 + "other" incl. bones as ray blockers), then Cycles
   selected-to-active EMIT bakes, cage extrusion 0.06, max ray 0.14, 2048².

**Equipment.** Objects are keyframed from the posed hands each frame
(`grip_point()` = knuckle line + palm offset). `CableTower.update(handle, frame)`
rebuilds the cable as a poly curve (stack → rear pulley → front pulley → handle) and
lifts the top plates by the change in cable length; call `calibrate()` with the
shortest-cable handle position first.

**Render.** Eevee, AgX, orthographic cameras (`camera(scene, name, target, yaw)`:
yaw 0 = in front of the body, 90 = its left side). 720×1280 per view now; the app
contract in plan.md wants 720×900.

## Gotchas learned the hard way

- Appended objects have no valid `matrix_world` until `view_layer.update()`.
- Clearing an object's parent keeps its local matrix: store `matrix_world` first, then restore it.
- Selected-to-active bakes cast every pixel against each source object separately:
  join meshes before baking (10 min → ~1 min per map).
- `BVHTree.FromObject` works in object-local space: transform rays.
- Z-Anatomy's own scene renders via Freestyle + a compositor (line art). Disable both.
- Many Z-Anatomy muscles have [muscle, tendon] material slots in varying order;
  check the slot material names.
- Cycles GPU (Metal) did not engage headless: bakes ran on CPU. Fine, but slow.
- In zsh, `$var` holding several args doesn't word-split: write args out or use `${=var}`.
- A zsh `cat > file` line without a heredoc blocks forever on stdin.
