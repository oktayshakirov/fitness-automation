# MVP delivery and review

Run from the repository root; `build.py` launches Blender with `.blender-profile`:

```sh
python3 catalog/validate.py
python3 build.py bodyweight_squat --delivery
python3 core/batch.py
python3 core/review_server.py 8765
```

Open http://127.0.0.1:8765/review/index.html. The batch is serial and resumes from
current asset fingerprints. A full build fits every camera to the animated body
and equipment, saves the scene, runs QA, renders all declared views at 720×900,
and encodes 30 fps H.264 and HEVC (`hvc1`) MP4 files. It produces first-frame WebP
posters and a 320×320 thumbnail. All loops contain one 72-frame / 2.4-second rep
(or hold cycle), no audio; videos must be ≤400,000 bytes and posters ≤40,000 bytes.
Frame folders are removed after successful encoding. Failed builds leave frames
for diagnosis and never publish new media. Review contact sheets and Blender
scenes remain in `review/`.

`dist/manifest.json` is an array with catalog identity/muscles/equipment, view names,
relative media paths, duration, approval, per-file SHA-256 and QA evidence.
Paths resolve relative to `dist/`. `loop_<view>.mp4` is the H.264 fallback;
`loop_<view>_hevc.mp4` is the optional HEVC variant. Ship `ATTRIBUTION.md` alongside
these files and include its credits in the app. The copy is generated by
`python3 core/package_notices.py`.

QA binds its result to the motion/catalog specification, rendering/posing code,
mask assets and saved Blender file. Approval flags are excluded from fingerprints.
Changed content must be rebuilt and reviewed. A manifest entry is a technically
validated draft until `approved` is true. The future app must filter on that flag
when it needs only human-approved content.

The review page shows every catalog record, all delivered camera views, coaching
text, exact specs and the QA report including exclusions. Selecting “I reviewed
all views, equipment contact and instructions” enables approval. Approval updates
`motion/specs/<id>.json:approved` and `catalog/<id>.json:reviewed`; revocation clears
both. The localhost server records an audit line in `review/approvals.jsonl`.
No exercise is auto-approved. Review server tests use temporary fixtures:

```sh
python3 core/test_delivery.py
python3 core/verify_delivery.py
```

The numerical gate is a screening tool: joint limits, floor/foot slide, implement
grips, loop closure, conservative hand/thigh collision and standing balance.
Supported/lying patterns exempt standing balance; per-spec exemptions and limits
are exposed in the report. It is not a full biomechanical simulation or a
replacement for inspecting seat/pad contact, form and muscle coverage.

`--quick` produces contact-sheet frames for iteration; `--no-render` produces a
posed scene. Neither exports app media. Rebuild with `--delivery` for publication.
The legacy review format remains available for older scripts.
